REMAINING / DIFFICULT ITEMS
---------------------------

A. DATA-LOADING ARCHITECTURE (largest remaining item)
   Current: the browser still calls fetchAllSupabaseData(), which downloads all
   seasons/teams/players/games (including box scores and play-by-play) and
   reloads everything when any public-schema row changes.
   Note: the public /uaap page now loads its archive data on the server. The
   admin UAAPArchiveManager still bundles the base JSON as an offline fallback
   and also calls /api/uaap/data; that admin-only double payload remains.
   Why not done here: moving to per-route server components changes every page
   and the admin optimistic-update flow; too risky to do in one pass.
   Recommended plan:
     1. Add server queries scoped by league + season (select only needed
        columns; games without play_by_play unless the modal is opened).
     2. Make Match Center, Standings, Players, Teams, and detail pages server
        components with Suspense; keep a small client cache for optimistic
        admin writes only.
     3. Replace the schema-wide realtime subscription with per-table filters,
        or use `revalidateTag("sports")` after admin writes instead of full
        client reloads.
     4. Add pagination/lazy loading for players and game lists.

B. REVOCABLE ADMIN SESSIONS
   Current: a stateless HMAC token (timestamp + HMAC of ADMIN_PASSWORD) is valid
   for 7 days; logout only deletes the cookie, so a copied cookie stays valid.
   Recommended:
     1. Generate a random session id and store it in a `admin_sessions` table
        (id, created_at, expires_at, revoked_at).
     2. Put the session id in the cookie; verify it against the DB in
        lib/admin-auth.ts/proxy.ts.
     3. Hash the admin password (Argon2id/scrypt) and store the hash in env or a
        secrets table; stop using the raw password as the HMAC key.
     4. Delete the session row on logout.

C. UAAP OVERRIDES: ONE ROW PER DIVISION
   Current: the whole overrides document is one JSON row. We added an in-process
   write queue and production failure semantics, but two serverless instances
   can still lose an update.
   Recommended:
     1. New table `uaap_division_overrides` keyed by
        (season, sport, division) with a `version`/`updated_at` column.
     2. Save only the affected division; use optimistic concurrency
        (`WHERE updated_at = expected`).
     3. Migrate the existing blob once, then keep the blob only as a read
        fallback.

D. TRANSACTIONAL SEASON/TEAM DELETION
   deleteSeasonInSupabase performs 4 sequential deletes with no transaction; a
   mid-way failure leaves partial data. Recommended: a Postgres function/RPC
   that deletes games, players, teams, and the season atomically, then call it
   from the app.

E. PLAYOFF/AUTO-LIVE STATUS POLICY
   getEffectiveGameStatus still returns UPCOMING for a game more than 4.5 hours
   past tip-off that was never marked FINAL. This is a product decision:
   - keep UPCOMING (current), or
   - add an OVERDUE/POSTPONED state (requires a type/UI change), or
   - mark FINAL only when a score was recorded.
   The PVL league-omission bug is fixed; the policy itself was left unchanged.

F. CONCURRENT TEAM-RECORD RECOMPUTES
   team records are recomputed in application code after game writes. Two
   concurrent admins can still produce a stale last-write-wins record.
   Recommended: move the win/loss recompute into a Postgres trigger or a
   transaction that locks the affected team rows, or derive records purely at
   read time and drop the denormalized column.

G. TESTS
   There are still no unit or E2E tests; playwright.config.ts points at a
   `tests/` directory that does not exist. Recommended:
     - Vitest for lib/derivations.ts, lib/admin-validation.ts,
       lib/box-score-parser.ts, lib/game-extractor.ts URL allowlist, and
       lib/uaap-schema.ts
     - Playwright smoke tests for `/`, `/standings`, `/uaap`, `/admin` login,
       and the game modal
     - a test that asserts a PVL fixture past tip-off stays UPCOMING

H. CSP NONCES
   The new CSP allows `'unsafe-inline'` for scripts because Next is not wired
   for nonces. To strengthen it, add a per-request nonce in proxy.ts and pass it
   to Next's script tags; then remove 'unsafe-inline'.

I. IMAGE HANDLING
   Team logos and player photos are rendered with plain <img> from arbitrary
   admin-entered hosts. This avoids next/image domain config but loses
   optimization and lets any https host be loaded. Consider proxying/caching
   images through an allowlisted loader.

J. UNIQUE CURRENT SEASON PER LEAGUE
   The app enforces one `isCurrent` season per league in memory; the DB has no
   constraint. Add a partial unique index on `(league)` where `is_current` (after
   backfilling null leagues) if this invariant must be guaranteed.
