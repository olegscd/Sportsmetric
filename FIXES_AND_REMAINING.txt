SPORTSMETRIC - FIXES AND DEPLOYMENT STATUS
========================================
Updated: 2026-10-19

The initial review fixes are in commit ccd9b43. This follow-up addresses the
unfinished A-J items from those notes and provides the missing CI template.

FOLLOW-UP IMPLEMENTED
---------------------
A. Scoped data loading
   - The root server shell streams initial data with Suspense; public pages
     start with the active season instead of downloading every league/year.
   - League/season selections call a scoped server endpoint. Player profiles
     load their career seasons; team profiles load their own season.
   - Public game queries omit play_by_play. Opening the play-by-play tab fetches
     it separately, with loading/error/retry states and request cancellation.
   - Realtime listens only to seasons/teams/players/games, with season filters
     where a single season is selected. Events during a reload queue a follow-up
     rather than being lost. Out-of-order responses cannot overwrite new scopes.
   - Player and match grids render 36 cards initially and expand on request.
   - Removed the admin archive's duplicate bundled JSON fallback; it loads the
     live archive once and reports a load failure.
   Design boundary: season box scores are still loaded for correct standings,
   averages and ranks. Card pagination limits rendering, not the season query.
   The authenticated admin workspace intentionally retains its full dataset.

B. Revocable sessions and password hashes
   - Cookies contain random 256-bit tokens; only SHA-256 digests are stored in
     a private RLS-protected admin_sessions table, with a seven-day expiry.
   - API proxy and server actions check the database session. Logout deletes
     the row before clearing the cookie; a copied cookie then fails validation.
   - ADMIN_PASSWORD_HASH supports salted scrypt and takes precedence over the
     legacy ADMIN_PASSWORD fallback. Passwords no longer sign cookies.
   - Added a stdin-based password-hash command and logout failure feedback.

C. Concurrent archive saves
   - One row per (season, sport, division), including deletion tombstones.
   - The migration copies legacy table/standing/award/chess overrides once.
   - A version-checked RPC saves only the selected division. Stale versions
     fail with an explicit reload message, including concurrent first inserts.
   - Editors pass the loaded version on save/delete. Awards can be explicitly
     cleared. Legacy blob/disk sources remain read fallbacks only.

D. Transactional deletion
   - Season deletion is one database RPC; an error rolls back every deletion.
   - Team deletion locks its row before checking scheduled games and deleting
     its players, preventing a check/delete race with new game references.

E. Auto-live policy retained and tested
   - PVL fixtures stay UPCOMING until official status changes.
   - Other leagues auto-show LIVE for the existing 4.5-hour active window.
   - An unconfirmed older fixture stays UPCOMING. Time alone never fabricates
     a final score/result. No new postponed/overdue product state was introduced.

F. Concurrent team-record updates
   - Game triggers lock affected teams before a game change, then recompute
     records in the same transaction. Old and new opponents are included.
   - Removed application-side read/recompute/upsert cycles, including batches.
   - Regular-season FINAL games count; playoff games do not.
   - PostgreSQL may abort a conflicting/deadlocked write rather than commit
     stale records; the existing admin error/rollback flow reports that failure.

G. Regression tests and CI
   - Added unit coverage for status policy (including PVL), standings, lifetime
     identity/weighted shooting, admin validation, pasted box scores, archive
     helpers, scrypt hashes, image policy, and source URL/redirect validation.
   - PGlite executes every migration from a fresh schema, checks current-season
     uniqueness, legacy archive migration, version conflicts, game-record
     triggers, session/RPC permissions and deletion rollback on mid-write errors.
   - Browser tests build the production app against isolated local fixture data
     and cover main pages, direct profile links, modal focus/close/lazy details,
     league scoping, protected APIs, login, logout and copied-cookie revocation.
   - Added docs/ci-workflow.yml, the CI workflow template missing from the
     earlier commit. GitHub rejected installing it under .github/workflows
     because the configured token lacks workflow permission. Activation awaits
     credentials that can create workflows.
   - Added the missing bootstrap schema before old ALTER TABLE migrations.

H. CSP nonces
   - Proxy generates a per-request nonce and forwards the CSP to Next rendering.
   - All HTML routes render dynamically, so framework scripts receive the nonce.
   - Removed script unsafe-inline; unsafe-eval is development-only. Inline
     styles remain allowed for the existing UI styles and export components.

I. Images
   - Avatars/logos use next/image optimization and caching with exact HTTPS
     hostnames. Private-IP fetching and redirects are disabled.
   - The same policy validates new admin-entered URLs. Legacy unapproved URLs
     show initials. Stat-card export uses the same optimized image URL.
   - Add extra hosts through NEXT_PUBLIC_IMAGE_HOSTS and rebuild.

J. Current season database invariant
   - Migration backfills league and deterministically demotes duplicate currents.
   - A partial unique index enforces one current season per league.
   - Season upserts/switches/reorders use one serialized transaction, demoting
     current flags before upsert so index enforcement is independent of row order.

Additional security fix:
   The earlier source allowlist checked only the initial URL. Import fetches now
   validate every redirect, reject credentials/custom ports, cap redirects and
   have a timeout. A regression test verifies private-host redirects are blocked.

RENDER-FAILURE FOLLOW-UP
------------------------
The live schema lacks games.venue (and other optional metadata columns). The
new public projection requested those columns explicitly and threw in the root
server shell. The loader now retries without missing optional columns and uses
legacy metadata inside box_score. The public live-data loader was verified
successfully (22 seasons, 10 active-season teams, 108 players, 8 games).
Initial database failures now keep the app shell/navigation and show a retry
message instead of reaching the global render-error screen. Browser fixtures
now model the legacy schema; an outage/recovery test verifies retry behavior.
The local production homepage and sports API both returned HTTP 200 using the
existing public database; the global render-error screen was absent.
